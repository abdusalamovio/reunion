# Reunion — проект Construct 3

2D-платформер в стимпанке. Играем за заводного робота Олли, который ищет
Оливера — мальчика, когда-то его собравшего. Прототип = первый уровень:
разбить механических жуков гаечным ключом.

## Главное, что нужно знать сразу

**Листов событий нет и не должно быть.** Вся логика в `scripts/основной.ts`.
Не создавай event sheets — проект сознательно построен на скриптах.

**Жёсткие лимиты бесплатной редакции Construct:** 2 слоя на макет, 50 событий,
2 эффекта, ~500 строк скрипта. Сейчас: 2 слоя, 0 событий, 0 эффектов, ~430
строк. Добавление третьего слоя сломает проект у владельца. Из-за лимита
параллакс эмулируется в коде (`UpdateParallax`), а не свойствами слоёв.

**Проверить в Construct нельзя.** В этом окружении нет редактора Construct, и
запустить игру невозможно. Единственная защита от поломки — валидатор
(`.claude/skills/project-audit/scripts/audit.py`). Гоняй его после каждой
правки JSON. Никогда не заявляй, что игра работает, — пиши «проверьте в
Construct».

## Структура

```
project.c3proj              индекс проекта: usedAddons, objectTypes, layouts
objectTypes/*.json          типы объектов (Sprite / Text)
images/*.png                картинки кадров, имя строго по шаблону
layouts/Макет 1.json        единственный макет: 2 слоя, вся геометрия
scripts/основной.ts         вся игровая логика
*.uistate.json              состояние редактора, в .gitignore, игнорировать
```

## Инварианты (ломаются чаще всего)

1. Имена в `project.c3proj → objectTypes.items` == имена файлов
   `objectTypes/*.json` == поле `name` внутри них.
2. Каждому кадру спрайта соответствует файл
   `images/<имя_объекта_в_нижнем_регистре>-<анимация>-<NNN>.png`,
   и его реальные размеры совпадают с `width`/`height` в кадре.
3. `uid` и `sid` уникальны среди всех экземпляров макета.
4. Все `type` экземпляров объявлены в `objectTypes.items`.
5. Каждое поведение, использованное в объекте, объявлено в `usedAddons`.
6. Папкой `images` управляют типы объектов. Удалишь тип — Construct выкинет
   его PNG при первом сохранении. Нужно сохранить картинку, но убрать объект с
   уровня — удаляй экземпляр, тип оставляй.

## Ловушки, на которых уже обожглись

**Слой адресуется по имени, не по индексу.** `createInstance(0, …)` сломался,
когда перед «Игрой» появились слои фона. Используй `GAME_LAYER = "Игра"`.

**Поворот на 180° зеркалит и по вертикали.** Для разворота спрайта влево
нельзя `angleDegrees = 180` — головка ключа окажется внизу. Зеркалирования в
API Sprite нет, отрицательная ширина не документирована. Правильно: отдельный
кадр с зеркальной картинкой + `animationFrame`, и хитбокс тоже зеркалить.

**Растянутые спрайты размазывают вертикальные детали.** Плиты пола растянуты
по X в десятки раз, поэтому их текстура — только горизонтальные полосы. Всё
круглое (болты, кронштейны) — отдельные нерастягиваемые экземпляры.

**Декор под платформами задевает жуков.** Кронштейны свисают на 36 px. Перед
тем как ставить декор, проверь коридоры патруля жуков (`audit.py` это делает).

**Граница карты.** Пол кончался ровно на границе макета, и шаг за край ронял
Олли в пустоту навсегда. Сейчас по бокам стоят невидимые `Ground` со `Solid`
плюс страховка `CheckFellOutOfLevel`. Не удаляй ни то, ни другое.

## Типы

Настоящие определения Construct (`ts-defs/`) появляются только после открытия
проекта в редакторе. Чтобы код проверялся и без этого, в репозитории лежит
временная заглушка `ts-defs/construct-stub.d.ts` и `tsconfig.json` под неё.
Оба файла в `.gitignore` и на GitHub не уходят.

Сейчас проект проходит `tsc --strict` с нулём ошибок.

**Добавил новый тип объекта — допиши его в `IProjectObjects` и `InstanceType`
внутри заглушки**, иначе обращение к нему станет ошибкой.

**Если после открытия в Construct полезли `Duplicate identifier`** — Construct
написал свои определения рядом. Удали `ts-defs/construct-stub.d.ts`, он больше
не нужен.

Проверить типы можно и отдельно:

```bash
cd <scratchpad> && npm i typescript@5 && ./node_modules/.bin/tsc \
  --noEmit --skipLibCheck --strict --target es2020 --module esnext \
  --moduleResolution bundler <проект>/ts-defs/*.d.ts <проект>/scripts/*.ts
```

## Как работать

- Правки JSON делай скриптом на Python с `json.load` / `json.dumps(indent="\t",
  ensure_ascii=False)`, а не текстовым поиском: отступы в макете — табы,
  имена — кириллица, ручная вставка уже один раз съела запятую.
- После любой правки — `python3 .claude/skills/project-audit/scripts/audit.py`.
- Картинки генерируй скриптом, а не ищи готовые: см. навык `pixel-art`.
- Хочешь показать, как выглядит игра, — собери кадр через навык
  `level-preview`, он рендерит настоящий макет.
- Временные файлы — в scratchpad сессии, не в репозиторий.

## Художественное направление

Холодный тёмный индустриальный фон (стена с окнами, трубы, шестерни, туман),
передний план почти чёрный силуэт с яркой холодной кромкой сверху. Единственные
тёплые пятна — латунь: Олли, ключ, глаза жуков, окантовка панциря, рамка
интерфейса. Референсы — Limbo / Inside по композиции, стимпанк по материалам.
Палитра зафиксирована в навыке `pixel-art`.
